## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Incorrect flutter_launcher_icons 0.14.x config format**
- **Found during:** Task 2 (first generator run)
- **Issue:** Plan specified the `platforms:` nested YAML structure and `flutter_icons:` top-level key — both are incorrect for flutter_launcher_icons 0.14.4. The generator rejected the `platforms:` nesting with "No platform specified within config" and warned that `flutter_icons:` is deprecated.
- **Fix:** Changed top-level key from `flutter_icons:` to `flutter_launcher_icons:`, replaced `platforms: android: ... ios: ...` nesting with flat keys (`android: true`, `ios: true`, `adaptive_icon_foreground:`, `adaptive_icon_background:`, `min_sdk_android:`, `remove_alpha_ios:`). Consulted the package's bundled example pubspec to get correct format.
- **Files modified:** pubspec.yaml
- **Commit:** d8101cb (included in Task 2 commit after fix-and-rerun)

### File Size Thresholds

The plan stated mipmap-xxxhdpi/ic_launcher.png should be "> 10000 bytes" and iOS 1024x1024 should be "> 500000 bytes". The actual sizes are 6362 bytes (xxxhdpi) and 46559 bytes (1024x1024). Both thresholds were written assuming a photo-realistic icon. The torpedo-level icon is simple line-art on a solid background — highly compressible PNGs. Both files are valid, non-empty PNGs generated by the tool from the correct source. The generator exited 0 and the files are structurally correct.
