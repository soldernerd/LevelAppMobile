</objective>

  </read_first>
  <action>
    Edit AndroidManifest.xml: (1) Add `xmlns:tools="http://schemas.android.com/tools"` to the root `<manifest>` opening tag (currently only declares `xmlns:android`) — required because the FileProvider uses `tools:replace` and that attribute namespace must be declared on the root element (Pitfall 7). (2) After the existing `BLUETOOTH_ADMIN` permission line, add `<uses-permission android:name="android.permission.REQUEST_INSTALL_PACKAGES" />` and `<uses-permission android:name="android.permission.INTERNET" />` — INTERNET is not currently declared and is required for release builds to perform the GitHub API call and APK download. (3) Inside `<application>`, after the `flutterEmbedding` meta-data element and before `</application>`, add a `<provider>` element with `android:name="androidx.core.content.FileProvider"`, `android:authorities="${applicationId}.fileProvider"`, `android:exported="false"`, `android:grantUriPermissions="true"`, and `tools:replace="android:authorities"`; its child `<meta-data>` has `android:name="android.support.FILE_PROVIDER_PATHS"`, `android:resource="@xml/filepaths"`, and `tools:replace="android:resource"` — the `tools:replace` attributes prevent manifest-merger conflicts with other plugins that also declare a FileProvider (Pitfall 1). Then create the new file android/app/src/main/res/xml/filepaths.xml (creating the res/xml/ directory) containing a `<paths>` root with a single `<cache-path name="apk_cache" path="." />` child — `<cache-path>` maps to `getCacheDir()`, the same directory `getTemporaryDirectory()` returns, where 07-02 will save the APK.
  </action>
